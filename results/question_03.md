# Вопрос 03: Какие тесты покрывают безопасность?

**Команда запуска:** `python -m hybrid_rag.demo`

**Цель:** продемонстрировать работу гибридного RAG — векторный поиск (ChromaDB) + графовый обход (Neo4j) с расширением результатов по связям IMPLEMENTS/COVERS.

## Ввод

Запрос пользователя (вопрос из `QUERIES`):

> Query: Какие тесты покрывают безопасность?

## Работа программы

### 1. Сравнение стратегий извлечения: Naive (только вектора) vs Hybrid (вектора + граф)

```text

│ Naive (vector only)                  │ Hybrid (vector + graph)              │
├──────────────────────────────────────┼──────────────────────────────────────┤

│ [NFR] NFR-004: Шифрование данных     │ [BR] BR-006: Безопасность данных     │
│ [BR] BR-005: Push-уведомления        │ [FR] FR-011: Настройка уведомлений   │
│ [TS] TS-031: Шифрование при передаче │ [FR] FR-012: Уведомление о           │
│                                      │ транзакции                           │
│ [NFR] NFR-010: Логирование           │ [FR] FR-013: Двухфакторная           │
│                                      │ аутентификация                       │
│                                      │ [NFR] NFR-004: Шифрование данных     │
│                                      │ [NFR] NFR-008: Безопасность сессии   │
│                                      │ [NFR] NFR-009: Уведомления           │
│                                      │ [NFR] NFR-010: Логирование           │
│                                      │ [TS] TS-021: Настройка уведомлений — │
│                                      │ включение                            │
│                                      │ [TS] TS-022: Настройка уведомлений — │
│                                      │ отключение                           │
│                                      │ [TS] TS-023: Уведомление о           │
│                                      │ транзакции                           │
```

### 2. Гибридный контекст, переданный в LLM

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ Hybrid context sent to LLM:                                                 │
│ - [BR] BR-005: Push-уведомления — информировать пользователей о важных      │
│ событиях (транзакции, оповещения безопасности) в реальном времени           │
│ - [BR] BR-006: Безопасность данных — обеспечить шифрование и хранение всех  │
│ пользовательских данных в соответствии со стандартами PCI DSS               │
│ - [FR] FR-011: Настройка уведомлений — система должна позволять             │
│ пользователям настраивать, какие уведомления получать (транзакции,          │
│ безопасность, акции), через меню настроек                                   │
│ - [FR] FR-012: Уведомление о транзакции — система должна отправлять         │
│ push-уведомление сразу после каждой успешной транзакции с суммой и данными  │
│ продавца                                                                    │
│ - [FR] FR-013: Двухфакторная аутентификация — система должна требовать      │
│ подтверждение через SMS-код при входе с нового устройства                   │
│ - [NFR] NFR-004: Шифрование данных — все данные должны шифроваться с        │
│ использованием AES-256 при хранении и TLS 1.3 при передаче                  │
│ - [NFR] NFR-008: Безопасность сессии — сессия пользователя должна           │
│ автоматически завершаться после 5 минут неактивности                        │
│ - [NFR] NFR-009: Уведомления — push-уведомления должны доставляться в       │
│ течение 5 секунд после события                                              │
│ - [NFR] NFR-010: Логирование — все действия пользователя должны             │
│ логироваться с временными метками для аудита безопасности                   │
│ - [TS] TS-021: Настройка уведомлений — включение — пользователь включает    │
│ уведомления о транзакциях в настройках. Push-уведомления начинают приходить │
│ - [TS] TS-022: Настройка уведомлений — отключение — пользователь отключает  │
│ уведомления о промоакциях. Push-уведомления о промо перестают приходить     │
│ - [TS] TS-023: Уведомление о транзакции — после успешного перевода          │
│ пользователь получает push-уведомление с суммой и названием получателя      │
│ - [TS] TS-024: Двухфакторная аутентификация — новый вход — вход с нового    │
│ устройства — система запрашивает SMS-код. После подтверждения — вход        │
│ выполнен                                                                    │
│ - [TS] TS-025: Двухфакторная аутентификация — неверный код — введён         │
│ неверный SMS-код 3 раза — вход блокируется на 15 минут                      │
│ - [TS] TS-031: Шифрование при передаче — перехват сетевого трафика          │
│ показывает TLS 1.3 — данные зашифрованы                                     │
│ - [TS] TS-032: Шифрование при хранении — прямой доступ к базе данных —      │
│ данные зашифрованы AES-256, не читаются без ключа                           │
│ - [TS] TS-037: Автозавершение сессии — пользователь не активен 5 минут —    │
│ сессия завершается, требуется повторный вход                                │
│ - [TS] TS-038: Доставка уведомлений — push-уведомление приходит в течение 5 │
│ секунд после транзакции                                                     │
│ - [TS] TS-039: Логирование действий — после входа, перевода и выхода в      │
│ логах видны все действия с временными метками                               │
└─────────────────────────────────────────────────────────────────────────────┘
```
