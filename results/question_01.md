# Вопрос 01: какие виды информирования пользователя есть в приложении

**Команда запуска:** `python -m hybrid_rag.demo`

**Цель:** продемонстрировать работу гибридного RAG — векторный поиск (ChromaDB) + графовый обход (Neo4j) с расширением результатов по связям IMPLEMENTS/COVERS.

## Загрузка и индексация данных

Запуск демо поднимает граф знаний и векторное хранилище:

```text
─────────────────────────────── Hybrid RAG Demo ───────────────────────────────
│ Vector search + Neo4j graph traversal.                                      │
│ Vector search finds semantically relevant requirements/tests,               │
│ graph traversal expands results through IMPLEMENTS and COVERS links.        │
└─────────────────────────────────────────────────────────────────────────────┘
knowledge graph ready
vector store ready: 69 documents
───────── Q: какие виды информирования пользователя есть в приложении ─────────
```

## Ввод

Запрос пользователя (вопрос из `QUERIES`):

> Query: какие виды информирования пользователя есть в приложении

### 2. Гибридный контекст, переданный в LLM

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ Hybrid context sent to LLM:                                                 │
│ - [BR] BR-004: Управление картами — позволить пользователям просматривать,  │
│ блокировать и разблокировать свои банковские карты прямо из приложения      │
│ - [BR] BR-005: Push-уведомления — информировать пользователей о важных      │
│ событиях (транзакции, оповещения безопасности) в реальном времени           │
│ - [FR] FR-008: Просмотр информации о карте — система должна отображать      │
│ информацию о карте: последние 4 цифры, срок действия, статус                │
│ (активна/заблокирована)                                                     │
│ - [FR] FR-009: Блокировка карты — система должна позволять пользователям    │
│ временно блокировать карту одним касанием, блокируя все входящие транзакции │
│ - [FR] FR-010: Разблокировка карты — система должна позволять пользователям │
│ разблокировать карту после временной блокировки через подтверждение PIN или │
│ биометрию                                                                   │
│ - [FR] FR-011: Настройка уведомлений — система должна позволять             │
│ пользователям настраивать, какие уведомления получать (транзакции,          │
│ безопасность, акции), через меню настроек                                   │
│ - [FR] FR-012: Уведомление о транзакции — система должна отправлять         │
│ push-уведомление сразу после каждой успешной транзакции с суммой и данными  │
│ продавца                                                                    │
│ - [NFR] NFR-009: Уведомления — push-уведомления должны доставляться в       │
│ течение 5 секунд после события                                              │
│ - [TS] TS-018: Просмотр информации о карте — пользователь открывает раздел  │
│ карт — видит последние 4 цифры, срок действия, статус                       │
│ - [TS] TS-019: Блокировка карты — пользователь нажимает «Заблокировать» —   │
│ карта блокируется, статус меняется на «Заблокирована»                       │
│ - [TS] TS-020: Разблокировка карты — пользователь блокирует карту, затем    │
│ разблокирует через подтверждение PIN. Статус возвращается в «Активна»       │
│ - [TS] TS-021: Настройка уведомлений — включение — пользователь включает    │
│ уведомления о транзакциях в настройках. Push-уведомления начинают приходить │
│ - [TS] TS-022: Настройка уведомлений — отключение — пользователь отключает  │
│ уведомления о промоакциях. Push-уведомления о промо перестают приходить     │
│ - [TS] TS-023: Уведомление о транзакции — после успешного перевода          │
│ пользователь получает push-уведомление с суммой и названием получателя      │
│ - [TS] TS-038: Доставка уведомлений — push-уведомление приходит в течение 5 │
│ секунд после транзакции                                                     │
└─────────────────────────────────────────────────────────────────────────────┘
```
